# 多版本配置管理器

一个不使用任何前端框架的纯 DOM 应用，用于管理包含多个分组和字段的配置版本，支持切换、回滚、差异对比、三路合并和状态导入导出。

## 技术栈

- IndexedDB：完整状态持久化，刷新后恢复当前版本、未提交草稿和合并会话。
- DOM/CSS：无框架、无构建步骤。
- Web Worker：版本差异、合并、冲突解析、导入校验等计算任务在 Worker 中执行，Worker 不可用时自动回退主线程。
- Canvas：绘制 DAG 版本树，展示普通提交、双父合并提交、回滚提交、根版本和 HEAD。

## 运行

需要通过 HTTP 提供文件，浏览器才能创建 Web Worker：

```bash
python3 -m http.server 8000
```

然后打开：

```text
http://localhost:8000/index.html
```

## 数据模型

- `groups[]`：配置分组，字段包含 `id`、`name`、`deleted`。
- `fields[]`：字段，类型支持 `text`、`number`、`boolean`、`json`，删除时保留带 `deleted: true` 的墓碑数据。
- `versions{}`：版本映射，每个版本包含不可变配置快照、`parentIds[]`、作者、说明和时间。
- `drafts{}`：按版本保存未提交编辑，切换版本不会覆盖草稿。
- `mergeSession`：进行中的三路合并，保存共同祖先、来源、目标、临时结果和冲突标记。

## 关键行为

- 切换：切换查看版本；每个版本的草稿独立保存。
- 提交：只有当前版本存在变化时才能提交新版本。
- 回滚：不覆盖或删除旧版本，而是从当前版本创建一个新的双父回滚提交，并复制目标版本配置。
- 对比：展示分组状态、字段增删、名称、类型和值变化。
- 合并：以共同祖先执行三路合并；快进时直接切换，分叉时创建合并会话。
- 冲突：字段值、字段名、字段删除与编辑并存、字段类型变化、双方同 ID 新增不一致、分组删除等都会标记；所有冲突必须显式选择处理方式后才能提交。
- 类型变化：切换字段类型时按安全规则转换；无法解析的 JSON 不会破坏旧值。
- 序列化：状态完全由 JSON 数据构成，导出文件带 schema，导入时执行版本链和可序列化校验。
